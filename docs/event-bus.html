Shulchan event bus

The phone sends HTTP and Socket.IO. Our server keeps a private tally of the table and sends PostHog three events: how the table went, when something failed, and a heartbeat that proves the process is up.

Where it sits

The device talks to our server the way it does today. It never calls PostHog. Each successful write updates the ledger on our server. A failed call sends error. The summary is sent when the table ends, including when the TTL sweep removes it with no phone connected.

Device — the phoneOur server — table servicePostHog — outside both

Three events

session.summaryOnce, when the table closes or expires. This is the product event: did people sit, play, and use video, or did the table sit empty?
errorWhen a request or a dependency fails. One name. area says auth, validation, forbidden, action, store, video, or subscriber.
server.heartbeatEvery 5 minutes from our server. redisOk and postgresOk. Quiet play is normal. A missing heartbeat means the process is down.

Folds, checks, streets, turns, joins, leaves, rebuys, sockets, and admin changes update a Redis tally only. They are not PostHog events. The tally is not part of the table record, and it is deleted after the summary is sent. Redis keeps it across a restart so a deploy does not wipe an open table.

Envelope

tableId is omitted on the heartbeat. Chip stacks, pots, blinds, scores, seat indexes, cards, dice, passwords, and LiveKit tokens are never properties.

Module

table/src/events/bus.tsTiny typed pub/sub. publish never throws into the game path. A subscriber exception is one error with area: "subscriber", then dropped.
table/src/events/ledger.tsRedis tally per table, separate from the table record. Not sent anywhere until close or expiry, then deleted.
table/src/events/posthog.tsSends only session.summary, error, and server.heartbeat. If POSTHOG_API_KEY is unset, it does nothing.

Rules

  • The ledger updates inside the existing change() wrapper and the route handlers. PostHog is not called from there.
  • The device does not send these events. A hand is counted once, on our server, inside the summary.
  • games is poker hands dealt, or backgammon matches finished. rounds is betting streets, or completed backgammon turns.
  • endReason is closed when the last player leaves, or expired when the five-hour TTL sweep removes the table.

PostHog

posthog-node on the table service only. POSTHOG_HOST defaults to the US ingest host. The game path never waits on PostHog. posthog.shutdown() on SIGTERM flushes the last summary.

distinct_idtable:{tableId} for a summary. server for the heartbeat and for an error that has no table.
Dedupe$insert_id is the envelope id, so a flush retry does not double-count a summary.

error

{
  "name": "error",
  "tableId": "K7M2PQ",
  "data": { "area": "store", "op": "read" }
}

area is auth, validation, forbidden, action, store, video, or subscriber. op or route is set when it helps. The message text is not sent. The same failure also increments errors on that table's summary.

What the ledger counts

These numbers are computed on our server from the game as it is played. Only the finished summary is sent.

peakPlayersHigh-water mark of people seated.
gamesPoker hands dealt, or backgammon matches finished.
roundsBetting streets, or completed backgammon turns.
joinRefusalsBad password, full table, join limit, or a rejected name.
errorsFailures charged to this table.
videoUsedTrue once any LiveKit token for this table succeeds.
endReasonclosed or expired.
durationMsFrom table create until the summary.

How many events

A poker night is one session.summary, plus an error only if something failed. The heartbeat is about 8,600 events a month at one every 5 minutes, whether or not anyone plays.

SituationEvents
One poker night, any number of hands1 summary
Eight nights in a month8 summaries, plus about 8,600 heartbeats
A month with nobody playingAbout 8,600 heartbeats and no summaries

When the server is off

A dead process cannot send an event. GET /health today returns ok without checking Redis or Postgres. Boot already waits on Redis, so a dead Redis at start means the process never listens.

What brokeWhat you see
Nobody is playingHeartbeats continue. Summaries stay at zero.
Process crashed, or the host is downNo heartbeat for 15 minutes. An outside probe of GET /health fails. The probe still fails if PostHog itself is unreachable.
Deploy or restartOne missed heartbeat, then they resume.
Redis or Postgres dies after bootHeartbeats continue with that flag false. Writes emit error with area: "store". /health can still return ok.
A handler bugerror climbs, split by area, while heartbeats stay green.
PostHog ingest is downThe game keeps running. Heartbeats go empty while /health stays green.

Left out on purpose

  • Per-action, per-hand, per-turn, per-join, and per-socket events. The summary already answers whether the table was used.
  • Chip stacks, pots, blinds, scores, seats, cards, and dice.
  • A PostHog SDK on the phone, session replay, and autocapture.
