Game separation

Where the server and the app end up, and the four phases to get there. Shared code never names a game. Each game is one folder on the server and one in the app, plus one line in a list of games on each side. To remove a game, delete its two folders and its two lines.

1 · Server (table/src)

The table service holds the shared parts of a table: seats, admin, pause, idle, video and the one stored deadline. It sends everything specific to a game to that game's module, and only the module talks to its engine.

Phone app

HTTP: open a table, join, get a LiveKit token, report or block a player. On the /table socket, game moves go in one move event, { type, … }. Shared table actions (pause, leave, admin) keep their own events.

Debug pages

/dev/<kind>: a plain router inside each game folder. The list of games mounts it, so it isn't part of the contract.

HTTP · socket /table
Shared table core: never imports a game folder
routes.ts

Open a table (the game checks its own settings), join (seat limits come from the game), LiveKit, report, block.

sockets.ts

Runs a move under the lock with helpers: requireAdmin, assertPlaying, noteActivity, resync. Pause, leave, admin.

store.ts

Lock, revision check, v: 2 records only. Old rows are deleted through the normal expiry path.

players.ts · seats.ts

Who sits where and the admin. A departing player is dropped once the game's unseat says the seat is free.

sweep · idle · livekit · events

Every replica arms the stored deadline on each broadcast; the sweep is the backstop. Idle closing, video, error codes, stats.

gameOf(table): the game's module, found by table.game.kind
Contract · games/types.ts
GameModule
  • seats: { min, max } players; anyone beyond max watches
  • open(settings): the game's state for a new table
  • seat(state, player) · unseat(state, player) → { state, freeNow }
  • status(state) → { phase, toAct, turnDeadline }: read by shared code
  • view(state, viewer): the game's part of the snapshot
  • moves[type] = { schema, run(ctx) }: run only changes the table it's given and returns a result for after the save
  • deadline?(state) → ms | null · onDeadline?(ctx): turn clock, auto-deal
  • tally(before, after) → { games, rounds }
  • engineHealthy(): reported, never gates /health

3 · Phases

Each phase is one push to main. Before every push: typecheck, lint and tests, then a check on the live server.

  1. 1

    Move the server codeserver

    No behaviour change. Snapshot, socket events and stored records stay as they are.

    • Create games/types.ts, games/index.ts, games/poker/ and games/backgammon/, and move each game's code into its folder.
    • Replace the "is it backgammon?" checks with calls to the game's module.
    • Add a test script to table/ and an import-graph test, starting with an allowlist of today's exceptions.

    Done when: the import test passes with only the allowlisted exceptions, and poker and backgammon play as before on the live server.

  2. 2

    Move the app codeapp

    Still on today's snapshot and socket events.

    • Move the shared table parts out of PokerTableLayout.tsx and table.tsx into client/src/table/.
    • Create games/poker/, games/backgammon/ and games/registry.ts; table.tsx becomes a thin screen.
    • Add the same import-graph test with an allowlist.

    Done when: the lobby, both tables, the admin and stats sheets and video look and work as before on a dev build.

  3. 3a

    Fix the server internalsserver

    The record changes, but the server still builds today's snapshot from it, so the current app keeps working.

    • The v: 2 record with game: { kind, … }. At boot, delete older rows through the expiry path (stats summaries still sent) and recreate the debug tables.
    • Backgammon tables stop running a hidden poker hand. Colours are stored when a game starts.
    • unseat → freeNow replaces reading poker's seats for every game.
    • One stored deadline per table: the turn clock and auto-deal, which now survives a restart.
    • GameError with codes; stats from tally; /health gated only by Redis and Postgres.
    • Remove the old Redis migration code and the poker:* keys.

    Done when: open, join, play, leave mid-game, pause and idle closing all work for both games on the live server, and auto-deal resumes after a restart.

  4. 3b

    Switch the contractserver + app, one push

    The app isn't published, so there's no old version to keep working.

    • Snapshot becomes { ...shared, status, game: { kind, … } }; ads, keep-awake and the turn chime read status.
    • One move event per game move. Errors are reported per kind.type so analytics keep their detail.
    • The app shows error text by code.
    • PUBLIC_CONFIG gets per-game sections; the Railway variable is updated in the same deploy (with your OK).

    Done when: both games play end to end on a dev build against the live server.

  5. 4

    Lock it inserver + app

    • Empty both import-graph allowlists.
    • Removal test: on a scratch branch, delete backgammon's two folders and two list lines, then check that typecheck and tests pass. The branch isn't committed.
    • Update the README and the architecture docs.

Considered and left out

A general scheduler

Two timers don't need one. A single stored deadline per table, checked by the existing sweep, fixes the restart bug. Revisit when a game needs a third kind of timer.

Moves as rule flags plus an "effects" system

Moves call helpers (requireAdmin, assertPlaying, noteActivity) and return a result for after the save, as today. Simpler to read than a block of flags.

Per-game string and sound files

Prefixed keys in the shared files are enough for two games. Leftover keys don't stop a game from being removed.

A "no game names" text check

It would trip on legal text, the website and comments. The import-graph test catches the coupling that matters.

Forcing a minimum app version

Not needed: the app isn't published.

Fewer engine calls per move

A move can make several engine calls under the 5-second lock. A real risk, but it exists today and isn't about separation. Its own task.

Removing a game, for example backgammon

  1. Delete table/src/games/backgammon/ and its line in games/index.ts.
  2. Delete client/src/games/backgammon/ and its entry in games/registry.ts.
  3. Delete backgammon-engine/, its line in scripts/dev.mjs, and the Railway service.
  4. Remove its bg* strings, its PUBLIC_CONFIG section and its pages on the website.

Typecheck and the import-graph test then pass with no other change. Phase 4 checks exactly this on a scratch branch.
